브라우저에서 이 파일을 그대로 연다. 앱 실행과는 별개다.

앱이 뜨는 순서 폴더를 나눈 이유 백엔드 주소 알림 주소와 로그인 이동 로그인 세션 회원가입 메인 홈 학습 설정 오답노트 학습 기록 화면 공유 분석 문제 풀이 가이드 ROI와 채점 용어 사전 채점 리뷰 아직 안 된 것

의료 영상 학습 앱

코드를 처음 보는 사람이 화면 하나씩 따라가도록 적은 설명서다. 기능을 고치면 그 절의 "무엇을 하나", "어느 파일인가", "동작 순서", "확인하는 법"을 같이 고친다.

앱이 뜨는 순서

무엇을 하나

브라우저가 Vue 앱을 붙이고, 주소에 맞는 화면 하나만 보여 준다. 공통 레이아웃은 없고 router-view만 있다.

어느 파일인가

  • src/main.js — 앱을 만들고 라우터를 연결한 뒤 #app에 붙인다.
  • src/App.vue — 화면 전환만 담당한다. 로그인 여부 판단은 하지 않는다.
  • public/index.html — #app이 있는 HTML 껍데기다.

동작 순서

  1. main.js가 createApp(App).use(router)를 호출한다.
  2. 지금 주소가 /, /login, /signup, /main, /learning, /medical, /medical/review, /analyze 중 무엇인지 라우터가 고른다.
  3. 고른 페이지 컴포넌트가 App.vue 안에 그려진다.

확인하는 법

npm run serve 후 주소만 바꿔 본다. 레이아웃이 페이지마다 완전히 달라지면 App.vue가 뼈대만 제공하고 있다는 뜻이다.

폴더를 나눈 이유

무엇을 하나

화면을 기능 폴더에 모아, 로그인 작업을 할 때 영상 채점 파일을 열지 않게 한다.

어느 파일인가

폴더맡은 일
src/components/login/로그인 화면과 사용자 세션
src/components/signup/회원가입 2단계 폼
src/components/main/로그인 후 홈(인사, 바로가기, 학습 현황, 이벤트 팝업, 문의 채팅)
src/components/learning/학습 설정(부위, 영상 종류)
src/components/Medical/문제, 영상, ROI, 용어 사전
src/components/Medical/review/채점 결과를 다시 보는 화면
src/components/analyze/화면 공유 후 네모 박스를 그려 분석하는 화면
src/components/note/오답·부분정답 카드를 보고 다시 푸는 화면
src/components/history/진도·정답률과 최근 제출을 보는 학습 기록
src/apiBase.js백엔드 주소 API_BASE. 요청 파일은 경로만 뒤에 붙인다
src/imageBase.js영상 파일 주소 IMAGE_BASE. 상대 경로는 이 버킷 뒤에 붙인다
src/notify.jsSweetAlert2 알림 showMessage

동작 순서

페이지 컴포넌트가 같은 폴더의 조각을 불러 조립한다. 예를 들어 로그인 페이지는 브랜드 영역과 입력 폼을 나란히 둔다. 세션을 읽고 쓰는 함수는 authSession.js 한곳에만 둔다. 채점 저장은 reviewModel.js만 맡는다.

확인하는 법

화면을 고칠 때 그 기능 폴더 밖 파일을 열어 보면 연결이 과한 것이다. 스타일은 각 .vue의 scoped CSS에 있다. 백엔드 호스트만 src/apiBase.js를, 영상 파일 호스트만 src/imageBase.js를 같이 쓴다.

백엔드 주소

무엇을 하나

로그인, 이벤트 팝업, 문의, 문제, 채점, 용어 요청이 같은 서버 주소를 쓴다. 주소를 바꿀 때는 한 줄만 고친다.

어느 파일인가

src/apiBase.js. 서버 호스트는 화면마다 다르지 않아서 기능 폴더 밖에 둔다. 각 요청 파일은 경로만 이 값 뒤에 붙인다.

동작 순서

  1. API_BASE 기본값은 http://127.0.0.1:8000이다.
  2. 로그인은 ${API_BASE}/login, 팝업은 /popups, 문의는 /qa, 문제는 /learning/problem, 오늘 현황은 /learning/today, 오답노트는 /learning/notes, 학습 기록은 /learning/history, 제출 이미지는 /learning/review, 채점은 /learning/roi-grade, 용어는 /glossary, 화면 분석은 /api/v1/analyze/screen-roi다.
  3. 영상 파일 주소는 이 값이 아니다. src/imageBase.js의 IMAGE_BASE이고, 값은 https://kr.object.ncloudstorage.com/biz02gj다.
export const API_BASE = 'http://127.0.0.1:8000'
const LOGIN_API = `${API_BASE}/login`

확인하는 법

API_BASE를 다른 주소로 바꾼 뒤 로그인하거나 /main을 새로고침한다. 개발자 도구 Network의 /login, /popups, /qa가 그 주소로 가야 한다. 값을 되돌리면 다시 127.0.0.1:8000으로 간다.

알림

무엇을 하나

브라우저 기본 alert 대신 화면 가운데 SweetAlert2 창으로 안내한다. 확인을 누르면 창이 닫힌다.

어느 파일인가

src/notify.js의 showMessage. 문구와 확인 버튼을 한곳에서 맞추려고 화면 파일은 이 함수만 호출한다. 라이브러리는 sweetalert2다.

동작 순서

  1. 학습 설정의 "가이드 보기"는 "사용 가이드 화면은 아직 연결 전입니다."를 띄운다.
  2. 풀이 화면 상단 "목록"은 "케이스 목록 화면은 아직 연결 전입니다."를 띄운다.
  3. 원본 이미지가 없거나 ROI가 없으면 경고 창을 띄우고 채점 요청은 보내지 않는다. ROI가 없으면 "ROI를 하나 이상 지정해 주세요."다.
  4. 슬라이스를 못 불러오거나 채점이 실패하면 오류 창에 서버 문장 또는 기본 실패 문장을 보여 준다.
showMessage('ROI를 하나 이상 지정해 주세요.', 'warning')
  → SweetAlert2 창, 버튼 글자는 확인

확인하는 법

로그인 후 /learning에서 "가이드 보기"를 누른다. 브라우저 기본 알림이 아니라 가운데 창과 "확인" 버튼이 나와야 한다. 확인을 누르면 창만 닫히고 화면은 그대로다. 풀이 화면에서 영상을 불러온 뒤 ROI 없이 제출해도 같은 형태의 창이 나와야 한다.

주소와 로그인 이동

무엇을 하나

주소로 화면을 고르고, 로그인된 사람이 로그인 화면에 머물지 않게 한다.

어느 파일인가

src/router/index.js. 경로 표가 여기 있어야 화면을 추가할 때 한곳만 고치면 된다.

동작 순서

  1. / 는 세션이 있으면 /main, 없으면 /login으로 보낸다.
  2. /login 은 이미 세션이 있으면 /main으로 보낸다.
  3. /signup은 회원가입이다. /main, /learning, /medical, /medical/review는 requireSession이 세션을 확인하고, 없으면 /login으로 보낸다. /analyze는 로그인 없이 연다.
  4. 풀이 주소의 region은 뇌·흉부·복부·무릎(brain, chest, abdomen, knee)이고 type은 CT 같은 영상 종류다.

확인하는 법

로그인 전 /main, /learning, /medical, /medical/review를 주소창에 입력하면 로그인 화면이 나와야 한다. 로그인한 뒤 같은 주소를 열면 각 화면이 열린다.

로그인

무엇을 하나

아이디와 비밀번호를 서버에 보내고, 성공하면 메인 홈(/main)으로 간다. 실패하면 이유를 폼 위에 보여 준다.

어느 파일인가

  • LoginPage.vue — 요청과 이동. 입력창 모양은 모른다.
  • LoginForm.vue — 아이디, 비밀번호, 가입 링크.
  • LoginBrandPanel.vue — 왼쪽 소개 영역.

동작 순서

  1. 폼이 login 이벤트로 아이디와 비밀번호를 올린다.
  2. 페이지가 POST ${API_BASE}/login에 { userId, userPw }를 보낸다. 호스트는 src/apiBase.js다.
  3. ok가 아니면 detail 또는 message를 보여주고, 둘 다 없으면 "아이디 또는 비밀번호가 올바르지 않습니다."를 쓴다.
  4. 성공하면 saveUserSession 후 /main으로 간다.

확인하는 법

백엔드가 127.0.0.1:8000에서 떠 있는 상태로 틀린 비밀번호와 맞는 계정을 각각 넣어 본다. 요청 중에는 로딩 상태가 폼에 전달된다.

세션

무엇을 하나

로그인한 사용자 정보를 브라우저 탭에만 남긴다. 새로고침해도 유지되고, 탭을 닫으면 사라진다.

어느 파일인가

src/components/login/authSession.js. 저장 형식을 한곳에서 맞춰야 헤더, 라우터, 문제 API가 같은 사용자를 본다.

동작 순서

  1. 키 이름은 medlens_user다.
  2. 저장하는 필드는 idx, user_id, user_name, mb_level뿐이다.
  3. 읽기에 실패하면 null을 반환한다.
  4. /main·/learning·/medical·/medical/review·/analyze 헤더에서 이름(또는 아바타)을 누르면 로그아웃이 나온다. 누르면 이 키와 채점 저장 medlens.review를 지우고 /login으로 간다. 이름은 세션이 있을 때만 그려서, 로그아웃 직후 user_name을 읽지 않는다.
sessionStorage.getItem('medlens_user')

확인하는 법

로그인 후 개발자 도구 Application 탭에서 해당 키를 본다. 값의 user_name이 헤더에 보여야 한다. /main·/learning·/medical·/medical/review·/analyze 어디에서든 로그아웃하면 키가 없어지고 로그인 화면으로 간다.

회원가입

무엇을 하나

계정 정보를 받고, 이어서 이름·학교 정보를 받는 두 단계 화면이다. 서버 가입은 아직 연결되어 있지 않다.

어느 파일인가

  • SignUpPage.vue — 위 제목과 가운데 폼을 배치한다.
  • TodoRegisterInput.vue — 단계 상태와 입력값을 가진다. 파일 이름은 예전 할 일 화면에서 남았다.
  • TodoHeader.vue — 회원가입 화면 상단이다.

동작 순서

  1. isFirstStep이 참이면 아이디, 비밀번호, 비밀번호 확인을 보여 준다.
  2. "다음"은 isFirstStep을 거짓으로 바꾼다. 필수값과 비밀번호 일치 검사는 주석으로 꺼져 있다.
  3. 2단계는 이름(최대 5자), 생년월일, 학교, 전공이다.
  4. "가입 완료"도 같은 nextStep을 호출하므로 2단계에 머문다. 가입 API 호출은 없다.
빈 값으로도 2단계로 넘어간다. 가입이 끝나도 로그인 화면으로 이동하지 않는다.

확인하는 법

/signup에서 "다음"과 "가입 완료"를 눌러 단계만 바뀌는지 본다. 로그인 링크는 /login으로 간다.

메인 홈

무엇을 하나

로그인한 사용자가 인사말·학습 바로가기·오늘의 학습 현황을 보는 홈 화면이다. 왼쪽 위에는 서버에서 받은 이벤트 홍보 팝업이 여러 장 뜨고, 제목 줄을 끌어 각 팝업을 옮길 수 있다. 헤더 "문의하기"로 채팅 창을 연다. 현황은 오늘 그 계정이 제출한 부위만 나온다. 오답노트는 /note, 학습 기록은 /history로 이동한다. 마이페이지 링크는 아직 목업이다.

어느 파일인가

  • src/components/main/indexPage.vue — 홈 레이아웃, 세션 이름, 바로가기, 부위별 현황 카드. 팝업과 채팅을 붙인다.
  • src/components/main/PageFrame.vue — 공통 헤더와 문의 채팅. 홈은 본문이 내용만큼 늘어나고, 학습·풀이·리뷰·화면 분석처럼 fill인 화면만 본문을 세로로 채워 높이를 고정한다.
  • src/components/main/MainHeader.vue — MedLens, 학습·오답노트·마이페이지·문의하기, 이름·로그아웃.
  • src/components/main/EventPromoPopups.vue — 이벤트 팝업 여러 장. 왼쪽 위에 두고, 제목 줄로 옮긴다. 닫기는 장마다 따로다.
  • src/components/main/eventPopups.js — GET /popups로 이벤트 목록을 받는다. "오늘 하루 보지 않기"만 그 날짜에 숨긴다.
  • src/components/main/InquiryChat.vue — 문의 채팅 창. 열고 있는 동안 최근 문의를 다시 읽는다.
  • src/components/main/inquiryChat.js — GET/POST ${API_BASE}/qa로 문의 스레드와 메시지를 다룬다.
  • src/components/main/todayStudyStats.js — 세션 idx로 GET /learning/today?user_idx=를 호출하고, 오늘 제출이 있는 부위만 남긴다.
  • src/router/index.js — /main 경로와 세션 검사.

동작 순서

  1. 주소가 /main이면 requireSession이 세션을 확인한다. 없으면 /login으로 보낸다.
  2. indexPage가 getUserSession()으로 이름을 읽어 "안녕하세요, {이름}님"을 보여 준다.
  3. "학습하기"와 "학습 시작"은 /learning으로 이동한다. 헤더의 "학습"도 같다.
  4. 헤더 오른쪽 이름·아바타를 누르면 로그아웃이 나온다. 누르면 세션과 채점 저장을 지우고 /login으로 간다.
  5. 오답노트는 /note로, 학습 기록 카드는 /history로 이동한다. 마이페이지는 화면이 없어 클릭해도 이동하지 않는다.
  6. fetchTodayStudyStats()가 세션 idx로 GET ${API_BASE}/learning/today?user_idx=를 호출한다. items의 part_label, study_minutes, problem_count, correct_rate를 학습 시간·학습 문제·정답률로 보여 준다. 오늘 제출이 없으면 안내 문구를 보여 준다.
  7. fetchVisibleEventPopups()가 GET ${API_BASE}/popups를 호출한다. 각 항목의 pp_title, pp_image_url, pp_link, start_at·end_at을 쓰고 pp_sort 순으로 화면 왼쪽 위부터 나란히 띄운다. 기간은 제목 옆에 붙인다. 오늘 "오늘 하루 보지 않기"를 누른 idx는 빼다.
  8. 제목 줄을 누른 채 움직이면 그 팝업만 따라간다. ×와 "참여하기", "오늘 하루 보지 않기", "닫기" 위에서는 끌기가 시작되지 않는다. 옮긴 위치는 새로고침하면 왼쪽 위로 돌아간다.
  9. 한 장의 × 또는 "닫기"는 그 장만 지금 화면에서 없앤다. 저장하지 않아서 홈을 다시 열면 그 장도 다시 뜬다. 다른 장은 그대로 남는다.
  10. "오늘 하루 보지 않기"는 그 장의 idx와 오늘 날짜를 localStorage 키 medlens.eventDismissToday에 남긴다. 같은 날짜에 새로고침해도 그 장만 나오지 않고, 다른 장은 나온다.
  11. pp_link가 없으면 "참여하기"는 없다. http로 시작하면 새 탭으로 열고, /learning 같은 경로는 앱 안에서 이동한다.
  12. 팝업 요청이 실패하면 팝업만 비우고 홈의 나머지 화면은 그대로 둔다.
  13. 헤더 "문의하기"는 채팅 창을 연다. 세션 idx로 GET ${API_BASE}/qa?user_idx=를 호출해 가장 최근 스레드를 고르고, GET /qa/{idx}?user_idx=의 메시지를 보여 준다. qm_role이 U면 오른쪽, A면 왼쪽 담당자 말풍선이다. 문의가 없으면 화면용 인사만 보여 준다.
  14. 첫 글과 종료(state가 S)된 뒤의 글은 POST /qa에 { user_idx, title, body }를 보낸다. title은 내용 앞 40자다. 진행 중인 문의의 다음 글은 POST /qa/{idx}/messages에 { user_idx, body }를 보낸다. 입력칸에 글을 쓰기 전에는 열 때 한 번만 읽고, 글을 입력한 뒤부터 5초마다 같은 문의를 다시 읽어 담당자 답을 붙인다.
GET ${API_BASE}/learning/today?user_idx=
  → { items: [{ st_part, part_label, study_minutes, problem_count, correct_rate }] }

GET ${API_BASE}/popups
  → [{ idx, pp_title, pp_image_url, pp_link, pp_sort, start_at, end_at }, ...]
fetchVisibleEventPopups()
  → pp_sort 순. localStorage medlens.eventDismissToday 에 오늘 날짜로 숨긴 idx는 뺀다
  ×·닫기 → 저장 없이 그 장만 화면에서 제거
  오늘 하루 보지 않기 → 그 idx만 오늘 날짜로 저장

GET ${API_BASE}/qa?user_idx=
  → { items: [{ idx, qt_title, state, ... }] }
GET /qa/{idx}?user_idx=
  → { thread, messages: [{ idx, qm_role, qm_body, created_at }] }
POST /qa  { user_idx, title, body }
POST /qa/{idx}/messages  { user_idx, body }
마이페이지 화면은 아직 없다. 문의가 하나도 없을 때의 인사 한 줄은 서버에 저장되지 않는다. 팝업 API, 문의 API, 오늘 현황 API가 꺼져 있으면 그 기능만 비고 홈의 나머지는 남는다.

확인하는 법

백엔드가 127.0.0.1:8000에서 떠 있는 상태로 로그인 후 /main을 연다. 오늘의 학습 현황 숫자가 /learning/today?user_idx=의 items와 같아야 하고, 오늘 제출이 없으면 "오늘 학습한 부위가 아직 없어요."가 보여야 한다. 화면 왼쪽 위에 /popups 항목 수만큼 팝업이 보이고, 제목 옆에 기간이, 그 아래 이미지가 응답과 같아야 한다. 제목 줄을 끌어 한 장만 다른 곳으로 옮겨지고 나머지는 그 자리에 있어야 한다. pp_link가 없는 항목에는 "참여하기"가 없다. 한 장만 × 또는 "닫기"를 누르면 그 장만 사라지고, 새로고침하면 그 장이 왼쪽 위에 다시 나와야 한다. 다른 장의 "오늘 하루 보지 않기"를 누른 뒤 새로고침하면 그 장만 오늘 다시 나오지 않아야 한다. 서버를 끄면 팝업은 없고 홈의 인사·바로가기는 남는다. 헤더 "문의하기"를 열면 그 계정(idx)의 최근 문의 메시지가 보여야 한다. 글을 보내면 오른쪽 말풍선에 쌓이고, 창을 닫았다가 다시 열어도 서버에 남은 글이 보인다. 담당자 답(qm_role A)은 왼쪽 말풍선이다.

  8. 상단 이름·아바타를 누르면 로그아웃이 나온다. 누르면 세션과 채점 저장을 지우고 /login으로 간다. 헤더는 홈과 같다.

무엇을 하나

학습 기록

무엇을 하나

지금까지 제출한 문제를 기간별로 모아, 진도·정답률·ROI 정확도와 최근 활동 표로 보여 준다. 화면 왼쪽은 학습 설정의 메뉴와 같고, 위 헤더는 홈과 같다.

어느 파일인가

  • src/components/history/LearningHistoryPage.vue — 기간 선택, 현황 카드, 최근 활동 표, 더보기.
  • src/components/history/history.js — GET /learning/history, 기간 거르기, 진도·정답률·ROI 정확도 계산.
  • src/components/learning/LearningSidebar.vue — 왼쪽 메뉴. "학습 기록"이 이 화면에서 켜진다.

동작 순서

  1. 주소 /history는 세션이 없으면 /login으로 보낸다. 홈의 학습 기록 카드와 왼쪽 메뉴 "학습 기록"도 이 주소로 온다.
  2. 세션 idx로 GET ${API_BASE}/learning/history?user_idx=를 호출한다. 응답은 그 사용자의 제출 전체(정답·부분정답·오답)와 활성 문제 수 total_studies다. 최신 제출이 앞이다.
  3. 기간은 전체, 최근 7일, 최근 30일이다. 고르면 현황과 표가 그 날짜의 제출만 쓴다.
  4. 진도는 기간 안 서로 다른 문제 수 / total_studies다. 정답률은 그 문제들의 가장 최근 결과가 정답(C)인 비율이다.
  5. ROI 정확도는 좌표 IoU 평균이 아니다. 서버는 IoU를 저장하지 않아서, 기간 안 제출 중 정답(C) 비율을 보여 준다.
  6. 표는 학습 일시, 케이스, 모드(문제 풀이), 소견, 결과다. 케이스 칸의 작은 그림은 image가 상대 경로면 IMAGE_BASE 뒤에 붙인다. 처음 4건만 보이고 "더보기"는 4건씩 연다. "전체 학습 기록 보기"는 남은 행을 한 번에 연다.
  7. 케이스 행을 누르면 region, type, idx, review로 /medical/review에 간다. review는 그 줄의 제출 번호다. 리뷰 화면이 이 번호로 저장해 둔 채점 이미지를 불러온다.
  8. 기간 안 제출이 없으면 "이 기간에 학습 기록이 없어요."를 보여 준다. API가 꺼지면 그 문장만 남고 메뉴는 그대로다.
GET ${API_BASE}/learning/history?user_idx=
  → { total_studies, items: [{ idx, study_idx, disease, solution, solution_label, part_label, modal_label, region, type, image, created_at }] }

확인하는 법

로그인 후 홈의 "학습 기록" 또는 왼쪽 메뉴를 누른다. 주소가 /history이고 메뉴의 학습 기록이 켜져 있어야 한다. 표의 행 수와 결과가 /learning/history?user_idx=와 같아야 한다. "최근 7일"을 바꾸면 그 기간 밖 행이 빠지고, 케이스 행은 /medical/review?region=...&type=...&idx=...&review=로 가고, 그 review 번호의 채점 이미지가 보여야 한다. 제출이 없으면 안내 문구만 보인다.

화면 공유 분석

무엇을 하나

파일을 올리지 않고 화면을 공유한 뒤, 그 위에 네모 박스를 그려 그 부분만 분석한다. 결과는 오른쪽 칸에 확률과 한국어 판독으로 나온다. 상단 헤더는 홈과 같은 MainHeader다.

어느 파일인가

  • src/components/analyze/ScreenAnalyzePage.vue — 화면 배치, 화면 공유, 드래그 박스, 결과 표시.
  • src/components/analyze/screenAnalyze.js — ROI 자르기 좌표와 POST /api/v1/analyze/screen-roi, POST /api/v1/analyze/screen-roi/explain.
  • src/router/index.js — /analyze. 세션 검사는 없다.

동작 순서

  1. 주소 /analyze는 로그인 없이도 열린다. 상단은 홈과 같은 MedLens, 학습, 오답노트, 마이페이지, 문의하기, 사용자 메뉴다.
  2. "화면 공유 시작"이 브라우저 화면 공유를 받는다. 취소하면 "화면 공유가 취소되었거나 권한이 없습니다."를 보여 준다.
  3. 공유된 영상 위에서 휠로 스크롤하고, 드래그로 네모 박스를 그린다. 가로·세로가 8픽셀보다 커야 분석 버튼이 켜진다.
  4. "선택 영역 분석"은 박스를 잘라 POST ${API_BASE}/api/v1/analyze/screen-roi로 보낸다. 오른쪽에는 잘라낸 그림, 이상 부위 오버레이, 출혈과 germinoma 확률을 보여 준다. 결과가 칸보다 길면 그 칸 안에서 스크롤한다.
  5. 분석이 끝나면 "AI 해설 (MedGemma)"가 켜진다. 누르면 POST ${API_BASE}/api/v1/analyze/screen-roi/explain으로 한국어 판독문을 받아 【】 구역으로 보여 준다.
  6. "박스 지우기"는 공유를 유지한 채 박스와 결과만 지운다. "공유 종료"는 공유 스트림과 결과를 처음 상태로 되돌린다.
화면 공유 → 드래그 ROI
  → POST ${API_BASE}/api/v1/analyze/screen-roi
  → POST ${API_BASE}/api/v1/analyze/screen-roi/explain
화면 공유는 Chrome·Edge에서 동작한다. 이 화면은 진단이 아니다.

확인하는 법

로그인 없이 http://localhost:8080/analyze를 연다. 상단 메뉴가 홈과 같아야 한다. 왼쪽 "1. 화면 캡처 & ROI 박스"와 오른쪽 "2. 분석 결과"가 흰 카드여야 한다. "화면 공유 시작"만 청록색이고 나머지 버튼은 처음에 꺼져 있다. 창을 고르면 영상이 나오고, 드래그한 뒤 분석을 누르면 오른쪽에 확률이 채워져야 한다. 백엔드가 꺼져 있으면 상태 줄에 "분석 실패"가 나온다.

문제 풀이

무엇을 하나

주소의 부위와 영상 종류에 맞는 문제 이미지를 받아 큰 뷰어에 보여 준다. MRI는 경로가 여러 장이면 슬라이스를 넘기며 본다.

어느 파일인가

  • CaseSolvingPage.vue — 문제를 불러오고 제출한다. MRI 경로 배열 파싱과 슬라이스 로드도 여기서 한다.
  • CaseInfoBar.vue — 문제 번호와 요약, 가이드, 케이스 목록.
  • XrayViewer.vue — 이미지와 ROI 레이어. 슬라이스가 많으면 하단 슬라이더와 휠로 장을 바꾼다.

동작 순서

  1. 쿼리에서 region, type을 읽고 없으면 brain, CT를 쓴다. idx가 있으면 그 문제 번호다.
  2. GET ${API_BASE}/learning/problem?st_part=...&st_modal=... 를 호출한다. 세션의 idx가 있으면 user_idx도 붙인다. 주소의 idx는 idx로 붙여 그 study 영상을 받는다. 호스트는 src/apiBase.js다.
  3. type이 MRI이면 problem.st_image를 경로 배열(또는 JSON·PostgreSQL 배열 문자열)로 풀고, 그 외 종류는 첫 경로 한 장만 쓴다.
  4. 지금 슬라이스 경로의 이미지 바이트를 내려받아 파일 객체로 화면에 그린다. 받은 장은 캐시에 두고, 앞뒤 몇 장은 미리 받는다. 슬라이스를 바꾸면 ROI는 지운다.
  5. 개발 서버에서는 바이트를 /stylesheets/...로 받는다. vue.config.js가 이 경로를 https://kr.object.ncloudstorage.com/biz02gj/stylesheets/...로 넘긴다. 요청 주소가 localhost라서 버킷의 CORS 헤더가 없어도 된다. 이 경로가 실패할 때만 버킷 주소를 직접 호출한다.
  6. 실패하면 "문제 불러오는 중" 대신 오류 문장을 보여 준다. 문제가 없으면 "풀 수 있는 새 문제가 없습니다."다.

확인하는 법

로그인한 뒤 개발자 도구 Network에서 영상 요청이 http://localhost:8080/stylesheets/...여야 하고, kr.object.ncloudstorage.com으로 가는 빨간 CORS 오류는 없어야 한다. /medical?region=chest&type=CT는 한 장만 보이고 슬라이더가 없어야 한다. /medical?region=brain&type=CT도 같다. idx를 붙이면 그 번호의 영상이 나와야 하고, 케이스 번호가 그 idx와 같아야 한다. 영상은 화면 안 뷰어에 보이고, 오른쪽 용어 목록이 길면 그 칸에서만 스크롤한다. /medical?region=brain&type=MRI에서 Network의 /learning/problem 응답 st_image가 [로 시작하는 배열(또는 JSON 배열 문자열)일 때만 하단에 슬라이더가 나온다. 경로 문자열 한 개면 슬라이더 없이 한 장만 보인다. 한 번 지나친 장은 다시 빠르게 나와야 한다. 상단 "목록"은 SweetAlert2로 "케이스 목록 화면은 아직 연결 전입니다."를 띄운다.

가이드

무엇을 하나

풀이 화면의 케이스 정보 줄에서 가이드를 누르면 원·박스 드래그, 제출, 리뷰 순서를 패널로 보여 준다. 상단 헤더는 홈과 같다.

어느 파일인가

src/components/Medical/CaseInfoBar.vue. 풀이 방법 안내라서 문제 정보 줄에 둔다. 리뷰 화면에는 이 버튼이 없다.

동작 순서

  1. 버튼을 누르면 guideOpen이 바뀌고 패널이 버튼 아래에 열린다.
  2. 패널은 영역 드래그, 마지막 ROI 제출, 리뷰 확인 세 줄을 보여 준다.
  3. 바깥을 누르거나 사용자 메뉴를 열면 패널이 닫힌다.

확인하는 법

로그인한 풀이 화면에서 케이스 정보 줄의 가이드를 눌러 세 줄이 보이는지 본다. 화면 빈 곳을 누르면 패널이 사라져야 한다. 상단 메뉴는 홈과 같아야 한다.

ROI와 채점

무엇을 하나

영상 위에 원이나 박스를 드래그해 관심 영역을 그리고, 마지막 영역만 서버에 보내 채점한다.

어느 파일인가

  • RoiToolbar.vue — 원, 박스, 지우기, 제출 버튼. 선택 도구는 부모의 tool과 연결된다.
  • RoiLayer.vue — 그린 도형을 이미지 위에 올린다.
  • CaseSolvingPage.vue — 화면 좌표를 이미지 비율 좌표로 바꿔 요청 본문을 만든다.

동작 순서

  1. 드래그가 끝나면 addRoi로 목록에 쌓인다. 지우기는 removeRoi다.
  2. 원본 이미지가 없거나 ROI가 없으면 showMessage로 SweetAlert2 창을 띄우고 요청하지 않는다.
  3. 여러 개면 마지막 ROI만 사용한다. 화면 아래 안내 문과 같다.
  4. 도형이 잘리지 않게 들어간 실제 그림 영역을 계산한 뒤, 왼쪽·위·너비·높이를 0에서 1 사이 비율로 바꾼다.
  5. 원은 중심 cx, cy와 radius로, 박스는 x, y, width, height로 FormData에 넣는다. 이미지 파일도 함께 보낸다.
  6. type이 MRI이면 slice_index(0부터)와 현재 슬라이스 image_path를 추가로 넣는다. CT는 이 두 필드를 보내지 않는다.
  7. POST ${API_BASE}/learning/roi-grade 가 끝나면 결과와 ROI, 슬라이스 정보를 sessionStorage 키 medlens.review에 저장하고 /medical/review로 이동한다.

확인하는 법

이미지를 불러온 뒤 제출만 누르면 SweetAlert2로 ROI 안내가 나온다. 박스를 그린 뒤 제출하면 주소가 /medical/review로 바뀌고, 개발자 도구에 medlens.review JSON이 생겨야 한다. MRI면 JSON에 sliceIndex, imagePath가 있어야 한다. 용량이 크면 오버레이 이미지 문자열은 빼고 다시 저장한다.

용어 사전

무엇을 하나

풀이 화면 오른쪽에 의학 용어 목록을 보여 준다. 문제 채점과는 별도 요청이다.

어느 파일인가

TermDictionary.vue. 풀이 페이지가 우측 칸으로 붙인다. 용어 데이터는 이 파일이 GET ${API_BASE}/glossary로 가져온다.

동작 순서

  1. 페이지가 열리면 용어 API를 호출한다.
  2. 서버가 배열 문자열로 준 값은 parsePgArray로 풀어 화면에 쓴다.
  3. 헤더와 같이 부위 코드 brain, chest, abdomen, knee를 한글 라벨로 바꾼다.

확인하는 법

풀이 화면에서 오른쪽 목록이 비거나 오류면 용어 API만 따로 의심하면 된다. 왼쪽 영상이 보여도 용어 요청은 따로 실패할 수 있다. 용어가 많으면 오른쪽 칸 안에서 스크롤하고, 영상 높이를 늘리지 않아야 한다.

채점 리뷰

무엇을 하나

방금 제출한 영상, 내가 그린 영역, 서버 오버레이, 정답 여부를 나란히 보여 준다. 학습 기록에서 들어온 주소에 review가 있으면 그 제출 번호의 채점 이미지를 다시 보여 준다. 요약에는 출혈(ICH) 확률과 생식세포종양(germinoma) 확률을 함께 보여 준다. MRI면 몇 번째 슬라이스를 냈는지도 보여 준다. 저장이 없으면 연습용 목업을 보여 준다.

어느 파일인가

  • CaseReviewPage.vue — 저장값을 읽어 두 패널에 넘긴다. "다음 문제 가져오기", 학습 기록에서 온 "다시 제출", "풀이완료"도 여기 둔다. 헤더는 홈과 같은 MainHeader다.
  • reviewModel.js — 저장 키, 목업(출혈·germinoma 포함), GET /learning/review, 오버레이·슬라이스 값 변환.
  • ReviewResultPanel.vue — 영상과 ROI, MRI 슬라이스 배지.
  • ReviewSummaryPanel.vue — 판정, IoU, 출혈(ICH)·Germinoma 소견, 제출 슬라이스.

동작 순서

  1. 제출 POST /learning/roi-grade는 채점 이미지와 함께 포함률, IoU, 위치 요약, 출혈·germinoma 소견, MRI 슬라이스 번호를 review_node에 넣는다.
  2. 주소에 review가 있으면 세션 idx로 GET ${API_BASE}/learning/review?idx=&user_idx=를 호출한다. idx는 제출 번호다. 응답 image가 채점 이미지이고, 상대 경로면 IMAGE_BASE 뒤에 붙인다. recall·iou·overlay_summary·findings·slice_index로 결과 요약을 그린다. 예전 제출은 이 값이 비어 포함률이 —다. 앱에 포함된 목업 그림(/medical/)은 버킷에 붙이지 않는다.
  3. review가 없으면 처음 데이터는 목업이다. usingMock이 참이고 판정은 "부분정답"이다. 목업에도 출혈·생식세포종양 예시가 있다.
  4. mounted에서 review가 없을 때만 medlens.review를 읽는다. gradeResult가 없으면 목업을 유지한다.
  5. 있으면 목업 표시를 끄고 저장한 채점, 이미지 경로, 사용자 ROI, 오버레이, sliceIndex/sliceTotal을 쓴다.
  6. 요약의 "주요 영상 소견"은 gradeResult.classification.findings(출혈 ICH)와 gradeResult.germinoma.findings(생식세포종양)를 확률 막대로 보여 준다. germinoma가 null이면 Germinoma 줄은 생략한다.
  7. 오버레이는 저장된 경로가 우선이고, 없으면 응답의 base64 PNG를 이미지 주소로 만든다.
  8. MRI이고 슬라이스 값이 있으면 결과 배지와 요약에 "슬라이스 N / M"을 보여 준다.
  9. "다음 문제"는 같은 region, type으로 /medical에 돌아간다. 주소에 review가 있으면 버튼은 "다시 제출"이고, 그 문제 idx로 /medical에 간다. 풀이 화면이 그 영상을 불러온 뒤, 제출은 그 이미지 파일을 POST /learning/roi-grade로 다시 보낸다.
  10. "학습 종료"는 onDone이 /main으로 보낸다. 세션은 유지된다.
gradeResult.classification.findings  → 출혈 (ICH) 막대
gradeResult.germinoma.findings       → Germinoma · 생식세포종양 막대

확인하는 법

로그인한 뒤 제출 없이 /medical/review를 열면 목업에 출혈·생식세포종양 예시가 보여야 한다. review를 붙이면 그 제출의 채점 이미지가 목업 대신 보여야 한다. 그때 "다시 제출"은 같은 idx의 풀이 화면으로 가고, 영역을 그려 제출하면 그 이미지가 /learning/roi-grade로 다시 가야 한다. 세션이 없으면 로그인 화면으로 간다. 풀이에서 제출한 직후라면 방금 그린 영역과 서버 판정이 보여야 하고, Network/medlens.review의 germinoma가 있으면 요약에 Germinoma 줄이 나와야 한다. "학습 종료"를 누르면 메인 홈(/main)으로 가야 한다.
