앱이 뜨는 순서

무엇을 하나

브라우저가 Vue 앱을 붙이고, 주소에 맞는 화면 하나만 보여 준다. 공통 레이아웃은 없고 router-view만 있다.

어느 파일인가

  • src/main.js — 앱을 만들고 라우터를 연결한 뒤 #app에 붙인다.
  • src/App.vue — 화면 전환만 담당한다. 로그인 여부 판단은 하지 않는다.
  • public/index.html — #app이 있는 HTML 껍데기다.

동작 순서

  1. main.js가 createApp(App).use(router)를 호출한다.
  2. 지금 주소가 /, /login, /signup, /main, /learning, /medical, /medical/review, /analyze, /note, /history, /glossary 중 무엇인지 라우터가 고른다.
  3. 고른 페이지 컴포넌트가 App.vue 안에 그려진다.

확인하는 법

npm run serve 후 주소만 바꿔 본다. 레이아웃이 페이지마다 완전히 달라지면 App.vue가 뼈대만 제공하고 있다는 뜻이다.

확인하는 법

백엔드 주소

무엇을 하나

로그인, 이벤트 팝업, 문의, 문제, 채점, 용어 요청이 같은 서버 주소를 쓴다. 같은 PC에서 열면 127.0.0.1:8000이고, 다른 PC에서 이 앱을 열면 그 PC의 127.0.0.1이 아니라 앱을 연 호스트의 8000포트를 쓴다.

어느 파일인가

src/apiBase.js. 서버 호스트는 화면마다 다르지 않아서 기능 폴더 밖에 둔다. 각 요청 파일은 경로만 이 값 뒤에 붙인다.

동작 순서

  1. 페이지 호스트가 127.0.0.1 또는 localhost이면 API_BASE는 http://127.0.0.1:8000이다. 그 외에는 http://연 호스트:8000이다. 주소에 ?api=http://서버:8000을 붙이거나 브라우저 localStorage의 medlens_api_base가 있으면 그 주소가 우선이다.
  2. 로그인은 ${API_BASE}/login, 팝업은 /popups, 문의는 /qa, 문제는 /learning/problem, 오늘 현황은 /learning/today, 오답노트는 /learning/notes, 학습 기록은 /learning/history, 제출 이미지는 /learning/review, 채점은 /learning/roi-grade, 용어는 /glossary, 화면 분석은 /api/v1/analyze/screen-roi다.
  3. 영상 파일 주소는 이 값이 아니다. src/imageBase.js의 IMAGE_BASE이고, 값은 https://kr.object.ncloudstorage.com/biz02gj다.
export const API_BASE = storedApiBase() || hostApiBase() || 'http://127.0.0.1:8000'
const LOGIN_API = `${API_BASE}/login`

확인하는 법

이 PC에서 http://127.0.0.1:8080을 열면 Network의 /login이 127.0.0.1:8000으로 가야 한다. 192.168.20.242:8080처럼 다른 주소로 열면 같은 호스트의 :8000으로 가야 한다. 서버가 다른 곳에 있으면 ?api=http://그주소:8000을 한 번 붙인 뒤 새로고침한다. localStorage의 medlens_api_base를 지우면 다시 호스트 규칙으로 돌아간다.

알림

무엇을 하나

브라우저 기본 alert 대신 화면 가운데 SweetAlert2 창으로 안내한다. 확인을 누르면 창이 닫힌다.

어느 파일인가

src/notify.js의 showMessage. 문구와 확인 버튼을 한곳에서 맞추려고 화면 파일은 이 함수만 호출한다. 라이브러리는 sweetalert2다.

동작 순서

  1. 학습 설정의 "가이드 보기"는 "사용 가이드 화면은 아직 연결 전입니다."를 띄운다.
  2. 풀이 화면 상단 "목록"은 "케이스 목록 화면은 아직 연결 전입니다."를 띄운다.
  3. 원본 이미지가 없거나 ROI가 없으면 경고 창을 띄우고 채점 요청은 보내지 않는다. ROI가 없으면 "ROI를 하나 이상 지정해 주세요."다.
  4. 슬라이스를 못 불러오거나 채점이 실패하면 오류 창에 서버 문장 또는 기본 실패 문장을 보여 준다.
showMessage('ROI를 하나 이상 지정해 주세요.', 'warning')
  → SweetAlert2 창, 버튼 글자는 확인

확인하는 법

로그인 후 /learning에서 "가이드 보기"를 누른다. 브라우저 기본 알림이 아니라 가운데 창과 "확인" 버튼이 나와야 한다. 확인을 누르면 창만 닫히고 화면은 그대로다. 풀이 화면에서 영상을 불러온 뒤 ROI 없이 제출해도 같은 형태의 창이 나와야 한다.

  6. fetchTodayStudyStats()가 세션 idx로 GET ${API_BASE}/learning/today?user_idx=를 호출한다. items의 part_label, study_minutes, problem_count, correct_rate를 학습 시간·학습 문제·정답률로 보여 준다. 오늘 제출이 없으면 안내 문구를 보여 준다.
  7. fetchVisibleEventPopups()가 GET ${API_BASE}/popups를 호출한다. 각 항목의 pp_title, pp_image_url, pp_link, start_at·end_at을 쓰고 pp_sort 순으로 화면 왼쪽 위부터 나란히 띄운다. 기간은 제목 옆에 붙인다. 오늘 "오늘 하루 보지 않기"를 누른 idx는 빼다.
  8. 제목 줄을 누른 채 움직이면 그 팝업만 따라간다. ×와 "참여하기", "오늘 하루 보지 않기", "닫기" 위에서는 끌기가 시작되지 않는다. 옮긴 위치는 새로고침하면 왼쪽 위로 돌아간다.
  9. 한 장의 × 또는 "닫기"는 그 장만 지금 화면에서 없앤다. 저장하지 않아서 홈을 다시 열면 그 장도 다시 뜬다. 다른 장은 그대로 남는다.
  10. "오늘 하루 보지 않기"는 그 장의 idx와 오늘 날짜를 localStorage 키 medlens.eventDismissToday에 남긴다. 같은 날짜에 새로고침해도 그 장만 나오지 않고, 다른 장은 나온다.
  11. pp_link가 없으면 "참여하기"는 없다. http로 시작하면 새 탭으로 열고, /learning 같은 경로는 앱 안에서 이동한다.
  12. 팝업 요청이 실패하면 팝업만 비우고 홈의 나머지 화면은 그대로 둔다.
  13. 헤더 "문의하기"는 채팅 창을 연다. 세션 idx로 GET ${API_BASE}/qa?user_idx=를 호출해 가장 최근 스레드를 고르고, GET /qa/{idx}?user_idx=의 메시지를 보여 준다. qm_role이 U면 오른쪽, A면 왼쪽 담당자 말풍선이다. 문의가 없으면 화면용 인사만 보여 준다.
  14. 첫 글과 종료(state가 S)된 뒤의 글은 POST /qa에 { user_idx, title, body }를 보낸다. title은 내용 앞 40자다. 진행 중인 문의의 다음 글은 POST /qa/{idx}/messages에 { user_idx, body }를 보낸다. 입력칸에 글을 쓰기 전에는 열 때 한 번만 읽고, 글을 입력한 뒤부터 5초마다 같은 문의를 다시 읽어 담당자 답을 붙인다.

화면 공유 분석

무엇을 하나

파일을 올리지 않고 화면을 공유한 뒤, 그 위에 네모 박스를 그려 그 부분만 분석한다. 결과는 오른쪽 칸에 확률과 한국어 판독으로 나온다. 상단 헤더는 홈과 같은 MainHeader다.

어느 파일인가

  • src/components/analyze/ScreenAnalyzePage.vue — 화면 배치, 화면 공유, 드래그 박스, 결과 표시.
  • src/components/analyze/screenAnalyze.js — ROI 자르기 좌표, 뇌 CT POST /api/v1/analyze/screen-roi와 해설, 흉부 준비·POST /api/v1/thorax/analyze/screen-roi, 뇌 MRI 준비·POST /api/v1/analyze/brain-mri, 무릎 POST /api/v1/knee/screen-roi.
  • src/router/index.js — /analyze. 세션 검사는 없다.

동작 순서

  1. 주소 /analyze는 로그인 세션이 있을 때만 열린다. 상단은 홈과 같은 Mediscan Note, 학습, 오답노트, 화면 분석, 마이페이지, 문의하기, 사용자 메뉴다. 홈 카드와 헤더의 "화면 분석"이 이 주소로 온다.
  2. "화면 공유 시작"이 브라우저 화면 공유를 받는다. 취소하면 "화면 공유가 취소되었거나 권한이 없습니다."를 보여 준다.
  3. 공유된 영상 위에서 휠로 스크롤하고, 드래그로 네모 박스를 그린다. 가로·세로가 8픽셀보다 커야 분석 버튼이 켜진다.
  4. "선택 영역 분석"은 왼쪽 "분석"에서 고른 대상으로 박스를 자른다. 뇌 CT는 POST ${API_BASE}/api/v1/analyze/screen-roi다. 흉부 X-ray는 GET ${API_BASE}/api/v1/thorax/health로 모델이 준비됐는지 본 뒤 POST ${API_BASE}/api/v1/thorax/analyze/screen-roi로 소견 박스와 점수를 받고, 판독 버튼은 없다. 뇌 MRI는 GET ${API_BASE}/api/v1/brain-mri/health 뒤 POST ${API_BASE}/api/v1/analyze/brain-mri로 5질환 위치와 점수를 받는다. 파일 이름은 mri.png이고, 시퀀스를 고를 수 있다. DICOM은 보내지 않는다. 무릎 MRI는 촬영면·범위와 함께 POST ${API_BASE}/api/v1/knee/screen-roi로 이상·ACL·반월판과 ACL 위치를 받는다. ACL 위치는 시상면과 슬라이스 전체일 때 의미가 있다.
  5. 뇌 CT 분석이 끝나면 "AI 해설 (MedGemma)"가 켜진다. 누르면 POST ${API_BASE}/api/v1/analyze/screen-roi/explain으로 한국어 판독문을 받아 【】 구역으로 보여 준다. 다른 대상에는 이 버튼이 없다.
  6. "박스 지우기"는 공유를 유지한 채 박스와 결과만 지운다. "공유 종료"는 공유 스트림과 결과를 처음 상태로 되돌린다.
화면 공유 → 드래그 ROI → 분석 대상
  뇌 CT     → POST /api/v1/analyze/screen-roi → explain
  흉부 X-ray → GET /api/v1/thorax/health → POST /api/v1/thorax/analyze/screen-roi
  뇌 MRI    → GET /api/v1/brain-mri/health → POST /api/v1/analyze/brain-mri
  무릎 MRI  → POST /api/v1/knee/screen-roi
화면 공유는 Chrome·Edge에서 동작한다. 이 화면은 진단이 아니다.

확인하는 법

로그인 없이 http://localhost:8080/analyze를 연다. 상단 메뉴가 홈과 같아야 한다. 분석 선택이 처음에 "뇌 CT"여야 하고, 흉부·뇌 MRI·무릎으로 바꾸면 AI 해설 버튼이 사라져야 한다. 뇌 MRI는 시퀀스, 무릎은 촬영면과 범위가 더 보인다. 창을 고르면 영상이 나오고, 드래그한 뒤 분석을 누르면 오른쪽에 점수가 채워져야 한다. 백엔드가 꺼져 있으면 상태 줄에 "분석 실패"가 나온다.

어느 파일인가

동작 순서

  1. 쿼리에서 region, type을 읽고 없으면 brain, CT를 쓴다. idx가 있으면 그 문제 번호다.
  2. idx가 없으면 GET ${API_BASE}/learning/problems?st_part=&st_modal=를 호출한다. 세션 idx가 있으면 user_idx도 붙인다. 목록에서 solved가 아닌 첫 문제를 고른다. 없으면 "풀 수 있는 새 문제가 없습니다."다. 정답 병명은 이 목록에 없다.
  3. 고른 번호 또는 주소의 idx로 GET ${API_BASE}/learning/problem/{번호}를 호출한다. 응답 problem에도 정답 병명은 없다. 삭제·비활성 문제면 404다.
  4. type이 MRI이면 problem.st_image를 경로 배열로 풀어 장 수를 정하고, 그 외는 첫 경로 한 장만 쓴다.
  5. type이 MRI이면 뷰어를 열기 전에 슬라이스를 모두 받는다. CT·X-ray도 같은 로딩 화면을 쓰고, 한 장만 받는다. st_image가 /stylesheets로 시작하면 그 경로를 한꺼번에 받는다. 개발 서버는 이 경로를 저장소로 넘겨 문제 API보다 빨리 온다. 그 경로가 실패하면 장마다 GET ${API_BASE}/learning/problem/{번호}/image?slice_index=를 최대 6개씩 받는다. slice_index는 0부터다. 한 장이라도 없으면 뷰어 대신 돌아가는 표시, "로딩중", 받은 장 수를 보여 준다. MRI는 예: 3 / 13, CT·X-ray는 0 / 1이다. 초로 세어 끄지 않고, 전부 받은 뒤에만 없어진다. 다 받으면 0번 장을 보여주고, 그 문제를 보는 동안 받은 장을 캐시에 둔다. MRI 슬라이더를 옮겨도 그 장 요청은 다시 나가지 않는다. 슬라이스를 바꾸면 ROI는 지운다. 제출할 MRI 경로는 여전히 st_image의 그 장 경로다.
  6. 실패하면 "로딩중" 대신 오류 문장을 보여 준다.

확인하는 법

로그인한 뒤 Network에서 문제가 /learning/problems 다음 /learning/problem/{번호}로 가고, 그림은 경로가 /stylesheets이면 그 주소, 아니면 /learning/problem/{번호}/image?slice_index=여야 한다. idx를 붙이면 목록 요청 없이 그 번호만 연다. /medical?region=chest&type=x-ray와 /medical?region=brain&type=CT도 뷰어 전에 MRI와 같은 "로딩중"이 보이고, 한 장이면 장 수는 1이다. 슬라이더는 MRI에서 st_image가 여러 장일 때만 나온다. /medical?region=brain&type=MRI는 장 수만큼 받은 뒤에 슬라이더가 나와야 하고, 그다음 슬라이더를 옮겨도 이미지 요청이 더 나가지 않아야 한다. 상단 "목록"은 SweetAlert2로 "케이스 목록 화면은 아직 연결 전입니다."를 띄운다.

ROI와 채점

무엇을 하나

영상 위에 원이나 박스를 드래그해 관심 영역을 그리고, 마지막 영역만 서버에 보내 채점한다.

어느 파일인가

  • RoiToolbar.vue — 원, 박스, 지우기, 제출 버튼. 선택 도구는 부모의 tool과 연결된다.
  • RoiLayer.vue — 그린 도형을 이미지 위에 올린다.
  • CaseSolvingPage.vue — 화면 좌표를 이미지 비율 좌표로 바꿔 요청 본문을 만든다.

동작 순서

  1. 드래그가 끝나면 addRoi로 목록에 쌓인다. 지우기는 removeRoi다.
  2. 원본 이미지가 없거나 ROI가 없으면 showMessage로 SweetAlert2 창을 띄우고 요청하지 않는다.
  3. 여러 개면 마지막 ROI만 사용한다. 화면 아래 안내 문과 같다.
  4. 도형이 잘리지 않게 들어간 실제 그림 영역을 계산한 뒤, 왼쪽·위·너비·높이를 0에서 1 사이 비율로 바꾼다.
  5. 원은 중심 cx, cy와 radius로, 박스는 x, y, width, height로 FormData에 넣는다. 이미지 파일도 함께 보낸다.
  6. type이 MRI이면 slice_index(0부터)와 현재 슬라이스 image_path를 추가로 넣는다. CT는 이 두 필드를 보내지 않는다.
  7. 부위와 영상 종류로 판독 주소를 고른다. 뇌 CT와 흉부 X-ray는 POST ${API_BASE}/learning/roi-grade다. 흉부는 서버가 흉부 모델로 채점한다. 뇌 MRI는 POST ${API_BASE}/api/v1/analyze/brain-mri로 PNG/JPEG 한 장을 판독하고, 뇌 CT 출혈 모델은 쓰지 않는다. 무릎 MRI는 CaseSolvingPage.vue의 requestReading이 gradeKneeRoi로 POST ${API_BASE}/learning/roi-grade/knee에 study_idx, roi_type=box, x, y, width, height, slice_index(0부터, 9번째 장은 8), user_idx(로그인한 회원 번호, 세션이 없으면 1)만 보낸다. 이미지 파일은 보내지 않는다. 서버는 user_idx를 review_node.rn_u_idx에 넣는다.
  8. readingGrade.js의 kneeAsGrade는 reading.findings가 있으면 result를 서버 값 그대로 둔다. 정답·부분정답·오답이면 그 배지를 쓴다. iou는 정확도, recall은 포함률, reference_bbox는 abnormality_bbox로 넘겨 정답 박스를 그린다. overlay_summary는 reading.summary다. reading이 없을 때만 미채점 분기를 쓴다.
  9. 끝나면 결과와 ROI, 슬라이스 정보를 sessionStorage 키 medlens.review에 저장하고 /medical/review로 이동한다. 흉부면 응답 learning_note가 소견 해설이다. 리뷰의 소견 제목은 classification.task가 thorax이면 흉부 소견, brain-mri이면 뇌 MRI, knee-mri이면 무릎 MRI, hemorrhage이면 출혈이다.

확인하는 법

이미지를 불러온 뒤 제출만 누르면 SweetAlert2로 ROI 안내가 나온다. 박스를 그린 뒤 제출하면 주소가 /medical/review로 바뀌고, 개발자 도구에 medlens.review JSON이 생겨야 한다. MRI면 JSON에 sliceIndex, imagePath가 있어야 한다. 무릎 MRI는 9번째 장(slice_index=8)에서 관절 가운데를 그리면 정답, 모서리만 그리면 오답이 나와야 한다. 문구는 뇌 CT와 같다. 정답은 "정답 병변을 잘 포함했습니다.", 부분정답은 일부만 겹친다는 문장, 오답은 거의 겹치지 않는다는 문장이다. 요약에는 포함률(recall)만 보이고 ROI 정확도 칸은 없다. iou는 저장 JSON에만 남는다. reference_bbox가 정답 박스로 그려진다. 소견 목록에 ACL 점수와 판정이 있고, 반월판은 시상면 모델이 없어 평가하지 않음이 정상이다. FastAPI를 재시작하지 않으면 회원 번호 없는 미채점 응답만 받는다. 용량이 크면 오버레이 이미지 문자열은 빼고 다시 저장한다.

용어 사전

무엇을 하나

풀이 화면 오른쪽에 의학 용어 목록을 보여 준다. 오른쪽 칸은 300px에서 360px이고, 영상은 남은 가로를 쓴다. 헤더 "용어 사전"은 같은 용어를 세 가지 화면으로 보여 준다. 문제 채점과는 별도 요청이다.

어느 파일인가

  • TermDictionary.vue. 풀이 페이지가 우측 칸으로 붙인다. GET ${API_BASE}/glossary/search만 호출한다.
  • src/components/glossary/GlossaryPage.vue. /glossary다. 위 버튼으로 세 칸(view=columns), 목록과 본문(view=reading), 카드(view=cards)를 바꾼다.
  • src/components/glossary/glossaryModel.js. /glossary 목록은 GET ${API_BASE}/glossary/search로 받고, 검색어가 있으면 q를 붙인다. 관련 용어와 표시 부위도 여기서 고른다.

동작 순서

  1. 풀이 화면이 열리면 TermDictionary가 주소 부위의 한글 이름으로 GET ${API_BASE}/glossary/search?q=를 한 번 호출한다. 이름이나 설명에 뇌·심장·폐·흉부·복부·무릎이 있으면 위 버튼과 카드 아래에 그 부위를 보여 준다. 버튼을 누르면 받은 목록 안에서만 거르고, 다시 요청하지 않는다. 검색칸에 글자를 넣으면 약 0.3초 뒤 그 글자만 q로 같은 주소를 다시 호출한다. 항목은 한글 이름 옆에 영어 이름을 괄호로 붙이고, 한글 설명 아래에 영어 설명을 둔다.
  2. 서버가 배열 문자열로 준 값은 parsePgArray로 풀어 화면에 쓴다.
  3. 헤더와 같이 부위 코드 brain, chest, abdomen, knee를 한글 라벨로 바꾼다.
  4. /glossary가 열리면 GET ${API_BASE}/glossary/search를 호출한다. 실패하면 오류 문장을 보여 준다.
  5. 검색칸에 글자를 넣으면 약 0.3초 뒤 GET ${API_BASE}/glossary/search?q=로 다시 받는다. 글자를 지우면 q 없는 주소로 돌아간다. 부위 버튼의 뇌·흉부·복부·무릎도 같은 주소로 다시 받고, q에는 그 한글 이름이 들어간다. 검색어와 부위를 같이 고르면 q에 둘을 한 칸 띄워 넣는다. 부위의 전체는 그 이름을 q에서 뺀다. 검색 종류의 전체는 서버 결과를 그대로 보여주고, 용어는 한글·영어 이름에 검색어가 있는 항목만, 증상은 한글·영어 설명에 있는 항목만 남긴다. 화면은 한글 이름 옆에 영어 이름을 괄호로 붙이고, 한글 설명 아래에 definition_en을 둔다. 세 칸은 왼쪽에서 부위를 고르고, 가운데 목록을 누르면 오른쪽에 설명과 관련 용어가 나온다. 목록과 본문은 왼쪽이 이름만 있는 목록이고 오른쪽이 본문이다. 카드는 왼쪽 검색 칸 옆에 격자가 있고, 카드를 누르면 오른쪽 아래에 설명이 겹친다. 다시 ×를 누르면 닫힌다.
  6. 관련 용어는 같은 분류 태그의 다른 항목이다. 설명 아래에 학습 화면으로 가는 버튼은 없다.

확인하는 법

풀이 화면 오른쪽 사전 요청은 /glossary/search뿐이어야 한다. 뇌 CT를 열면 q=뇌다. 폐 버튼을 눌러도 새 요청은 없고, 설명에 폐가 있는 항목만 남아야 한다. 검색어를 넣으면 q는 그 검색어만이다. 목록이 비거나 오류면 용어 API만 따로 의심하면 된다. 왼쪽 영상이 보여도 용어 요청은 따로 실패할 수 있다. 오른쪽 칸은 300px에서 360px이고 영상은 그 옆의 남은 가로여야 한다. 용어가 많으면 오른쪽 칸 안에서 스크롤하고, 영상 높이를 늘리지 않아야 한다. 헤더 "용어 사전"은 /glossary다. "세 칸", "목록과 본문", "카드"를 누르면 주소의 view가 바뀌고 배치가 달라져야 한다. 카드 화면은 검색 칸이 격자 왼쪽에 있어야 한다. 처음 요청은 /glossary/search이고, 검색어를 넣으면 /glossary/search?q=가 가야 한다. 부위의 뇌를 누르면 q가 뇌인 같은 주소로 다시 가야 하고, 목록이 그 결과로 바뀌어야 한다. "용어"는 한글·영어 이름만, "증상"은 한글·영어 설명만 남겨야 한다. 항목은 한글 이름 옆에 영어 이름이 괄호로 보이고, 한글 설명 아래에 영어 설명이 있어야 한다. 용어를 고르면 설명과 관련 용어가 보이고, "이 부위로 학습하기"는 없어야 한다. 세션이 없으면 로그인 화면으로 간다.

채점 리뷰

무엇을 하나

방금 제출한 영상, 내가 그린 영역, 서버 오버레이, 정답 여부를 보여 준다. 배치는 풀이 화면과 같다. 위 정보 줄에 판정과 다음 문제·풀이완료가 있고, 오른쪽 요약은 300px에서 360px, 영상은 남은 가로다. 영상 왼쪽에는 풀이와 같은 확대, 축소, 기본크기, 팬, 밝기, 리셋이 있다. 학습 기록에서 들어온 주소에 review가 있으면 그 제출 번호의 채점 이미지를 다시 보여 준다. 요약에는 추정 병명, 포함률, 출혈(ICH) 확률과 생식세포종양(germinoma) 확률을 보여 준다. ROI 정확도 칸은 없다. MRI면 몇 번째 슬라이스를 냈는지도 보여 준다. 저장이 없으면 연습용 목업을 보여 준다.

어느 파일인가

  • CaseReviewPage.vue — 저장값을 읽어 두 패널에 넘긴다. "다음 문제 가져오기", 학습 기록에서 온 "다시 제출", "풀이완료"도 여기 둔다. 헤더는 홈과 같은 MainHeader다.
  • reviewModel.js — 저장 키, 목업(출혈·germinoma 포함), GET /learning/review, 오버레이·슬라이스 값 변환.
  • ReviewResultPanel.vue — 영상과 ROI, MRI 슬라이스 배지, 무릎 판독 목록. 영상 도구는 풀이와 같은 XrayViewer.vue다. 그리기는 끄고 확대·축소·기본크기·팬·밝기·리셋만 쓴다.
  • ReviewSummaryPanel.vue — 추정 병명, 포함률, 출혈(ICH)·Germinoma 소견, 제출 슬라이스. ROI 정확도 칸은 그리지 않는다.

동작 순서

  1. 제출 POST /learning/roi-grade는 채점 이미지와 함께 포함률, IoU, 위치 요약, 출혈·germinoma 소견, MRI 슬라이스 번호를 review_node에 넣는다.
  2. 주소에 review가 있으면 세션 idx로 두 요청을 한다. 채점 이미지는 GET ${API_BASE}/learning/review?idx=&user_idx=다. idx는 제출 번호다. 응답 image가 채점 이미지이고, 상대 경로면 IMAGE_BASE 뒤에 붙인다. recall·iou·overlay_summary·findings·slice_index로 결과 요약을 그린다. 다시 풀 수 있는지는 GET ${API_BASE}/learning/reviews/{번호}?user_idx=의 problem이다. problem이 없으면 "다시 제출"을 숨긴다. 이 상세 요청이 실패하면 예전처럼 저장 응답의 문제 번호로 다시 제출할 수 있다. 예전 제출은 요약 칸이 비어 포함률이 —다.
  3. review가 없으면 처음 데이터는 목업이다. usingMock이 참이고 판정은 "부분정답"이다. 목업에도 출혈·생식세포종양 예시가 있다.
  4. mounted에서 review가 없을 때만 medlens.review를 읽는다. gradeResult가 없으면 목업을 유지한다.
  5. 있으면 목업 표시를 끄고 저장한 채점, 이미지 경로, 사용자 ROI, 오버레이, sliceIndex/sliceTotal을 쓴다.
  6. 요약의 "병명 해설"은 gradeResult.learning_note가 있으면 그 이름, 요약, 영상 소견, 함정을 보여 준다. "주요 영상 소견" 제목은 classification.task를 따른다. hemorrhage만 출혈(ICH)과 Germinoma 막대이고, thorax는 흉부 소견, brain-mri는 뇌 MRI, knee-mri는 무릎 MRI다. germinoma가 null이면 Germinoma 줄은 생략한다.
  7. 무릎 MRI의 result가 정답·부분정답·오답이면 배지와 문구는 뇌 CT와 같다. 정답은 "정답 병변을 잘 포함했습니다.", 부분정답은 일부만 겹친다는 문장, 오답은 거의 겹치지 않는다는 문장이다. recall은 포함률이다. iou는 저장만 하고 요약의 ROI 정확도 칸은 그리지 않는다. abnormality_bbox가 있으면 정답 박스로 그린다. 소견 목록은 label_ko, verdict, prob다. status가 not_evaluated이면 점수 대신 reason이다. 뇌 MRI의 판독 문장은 무릎에 쓰지 않는다.
  8. 오버레이는 저장된 경로가 우선이고, 없으면 응답의 base64 PNG를 이미지 주소로 만든다.
  9. 리뷰 영상은 XrayViewer.vue다. drawable은 거짓이라 새로 그리지 않는다. 확대·축소·기본크기는 zoom을 바꾸고, 팬은 영상을 끌어 옮기고, 밝기는 brightness와 contrast를 바꾼다. 리셋은 배율 1, 위치 원점, 밝기 기본으로 되돌린다. 사용자 ROI와 정답 표시는 같은 stage 안에 있어 확대·이동과 함께 움직인다.
  10. MRI이고 슬라이스 값이 있으면 결과 배지와 요약에 "슬라이스 N / M"을 보여 준다.
  11. "다음 문제"는 같은 region, type으로 /medical에 돌아간다. 주소에 review가 있으면 버튼은 "다시 제출"이고, 그 문제 idx로 /medical에 간다. 풀이 화면이 그 영상을 불러온 뒤, 제출은 그 이미지 파일을 POST /learning/roi-grade로 다시 보낸다.
  12. "학습 종료"는 onDone이 /main으로 보낸다. 세션은 유지된다.
gradeResult.classification.findings  → 출혈 (ICH) 막대
gradeResult.germinoma.findings       → Germinoma · 생식세포종양 막대

확인하는 법

로그인한 뒤 제출 없이 /medical/review를 열면 목업에 출혈·생식세포종양 예시가 보여야 한다. 넓은 화면에서 오른쪽 요약은 300px에서 360px이고 영상은 남은 가로다. 영상 왼쪽에 확대, 축소, 기본크기, 팬, 밝기, 리셋이 있고, 확대를 누르면 Zoom 숫자가 커져야 한다. 사용자 영역과 정답 표시는 확대·이동 뒤에도 영상과 함께 움직여야 한다. 위 정보 줄의 버튼 배치는 풀이 화면과 같아야 한다. 좁은 화면에서는 영상 아래에 요약이 이어진다. 요약에 "ROI 정확도"는 없고 추정 병명과 포함률만 있어야 한다. review를 붙이면 그 제출의 채점 이미지가 목업 대신 보여야 한다. 그때 "다시 제출"은 같은 idx의 풀이 화면으로 가고, 영역을 그려 제출하면 그 이미지가 /learning/roi-grade로 다시 가야 한다. 세션이 없으면 로그인 화면으로 간다. 풀이에서 제출한 직후라면 방금 그린 영역과 서버 판정이 보여야 하고, Network/medlens.review의 germinoma가 있으면 요약에 Germinoma 줄이 나와야 한다. "학습 종료"를 누르면 메인 홈(/main)으로 가야 한다.
