브라우저에서 이 파일을 그대로 연다. 앱 실행과는 별개다.

앱이 뜨는 순서 폴더를 나눈 이유 주소와 로그인 이동 로그인 세션 회원가입 문제 풀이 ROI와 채점 용어 사전 채점 리뷰 아직 안 된 것

의료 영상 학습 앱

코드를 처음 보는 사람이 화면 하나씩 따라가도록 적은 설명서다. 기능을 고치면 그 절의 "무엇을 하나", "어느 파일인가", "동작 순서", "확인하는 법"을 같이 고친다.

앱이 뜨는 순서

무엇을 하나

브라우저가 Vue 앱을 붙이고, 주소에 맞는 화면 하나만 보여 준다. 공통 레이아웃은 없고 router-view만 있다.

어느 파일인가

  • src/main.js — 앱을 만들고 라우터를 연결한 뒤 #app에 붙인다.
  • src/App.vue — 화면 전환만 담당한다. 로그인 여부 판단은 하지 않는다.
  • public/index.html — #app이 있는 HTML 껍데기다.

동작 순서

  1. main.js가 createApp(App).use(router)를 호출한다.
  2. 지금 주소가 /, /login, /signup, /medical, /medical/review 중 무엇인지 라우터가 고른다.
  3. 고른 페이지 컴포넌트가 App.vue 안에 그려진다.

확인하는 법

npm run serve 후 주소만 바꿔 본다. 레이아웃이 페이지마다 완전히 달라지면 App.vue가 뼈대만 제공하고 있다는 뜻이다.

폴더를 나눈 이유

무엇을 하나

화면을 기능 폴더에 모아, 로그인 작업을 할 때 영상 채점 파일을 열지 않게 한다.

어느 파일인가

폴더맡은 일
src/components/login/로그인 화면과 사용자 세션
src/components/signup/회원가입 2단계 폼
src/components/Medical/문제, 영상, ROI, 용어 사전
src/components/Medical/review/채점 결과를 다시 보는 화면

동작 순서

페이지 컴포넌트가 같은 폴더의 조각을 불러 조립한다. 예를 들어 로그인 페이지는 브랜드 영역과 입력 폼을 나란히 둔다. 세션을 읽고 쓰는 함수는 authSession.js 한곳에만 둔다. 채점 저장은 reviewModel.js만 맡는다.

확인하는 법

화면을 고칠 때 그 기능 폴더 밖 파일을 열어 보면 연결이 과한 것이다. 스타일은 각 .vue의 scoped CSS에 있다.

주소와 로그인 이동

무엇을 하나

주소로 화면을 고르고, 로그인된 사람이 로그인 화면에 머물지 않게 한다.

어느 파일인가

src/router/index.js. 경로 표가 여기 있어야 화면을 추가할 때 한곳만 고치면 된다.

동작 순서

  1. / 는 세션이 있으면 /medical?region=brain&type=CT, 없으면 /login으로 보낸다.
  2. /login 은 이미 세션이 있으면 같은 풀이 주소로 보낸다.
  3. /signup, /medical, /medical/review 는 각각 회원가입, 문제 풀이, 채점 리뷰다.
  4. 풀이 주소의 region은 뇌·흉부·복부·무릎(brain, chest, abdomen, knee)이고 type은 CT 같은 영상 종류다.
/medical과 /medical/review는 세션이 없어도 들어간다. 로그인 강제 이동은 아직 라우터에 없다.

확인하는 법

로그인 전후 /와 /login을 직접 입력한다. 세션을 지운 뒤 /medical을 열면 지금은 풀이 화면이 그대로 열린다.

로그인

무엇을 하나

아이디와 비밀번호를 서버에 보내고, 성공하면 풀이 화면으로 간다. 실패하면 이유를 폼 위에 보여 준다.

어느 파일인가

  • LoginPage.vue — 요청과 이동. 입력창 모양은 모른다.
  • LoginForm.vue — 아이디, 비밀번호, 가입 링크.
  • LoginBrandPanel.vue — 왼쪽 소개 영역.

동작 순서

  1. 폼이 login 이벤트로 아이디와 비밀번호를 올린다.
  2. 페이지가 POST http://127.0.0.1:8000/login에 { userId, userPw }를 보낸다.
  3. ok가 아니면 detail 또는 message를 보여주고, 둘 다 없으면 "아이디 또는 비밀번호가 올바르지 않습니다."를 쓴다.
  4. 성공하면 saveUserSession 후 /medical?region=brain&type=CT로 간다.

확인하는 법

백엔드가 127.0.0.1:8000에서 떠 있는 상태로 틀린 비밀번호와 맞는 계정을 각각 넣어 본다. 요청 중에는 로딩 상태가 폼에 전달된다.

세션

무엇을 하나

로그인한 사용자 정보를 브라우저 탭에만 남긴다. 새로고침해도 유지되고, 탭을 닫으면 사라진다.

어느 파일인가

src/components/login/authSession.js. 저장 형식을 한곳에서 맞춰야 헤더, 라우터, 문제 API가 같은 사용자를 본다.

동작 순서

  1. 키 이름은 medlens_user다.
  2. 저장하는 필드는 idx, user_id, user_name, mb_level뿐이다.
  3. 읽기에 실패하면 null을 반환한다.
  4. 헤더에서 로그아웃하면 이 키와 채점 저장 medlens.review를 지우고 /login으로 간다.
sessionStorage.getItem('medlens_user')

확인하는 법

로그인 후 개발자 도구 Application 탭에서 해당 키를 본다. 값의 user_name이 헤더에 보여야 한다. 로그아웃하면 키가 없어진다.

회원가입

무엇을 하나

계정 정보를 받고, 이어서 이름·학교 정보를 받는 두 단계 화면이다. 서버 가입은 아직 연결되어 있지 않다.

어느 파일인가

  • SignUpPage.vue — 위 제목과 가운데 폼을 배치한다.
  • TodoRegisterInput.vue — 단계 상태와 입력값을 가진다. 파일 이름은 예전 할 일 화면에서 남았다.
  • TodoHeader.vue — 회원가입 화면 상단이다.

동작 순서

  1. isFirstStep이 참이면 아이디, 비밀번호, 비밀번호 확인을 보여 준다.
  2. "다음"은 isFirstStep을 거짓으로 바꾼다. 필수값과 비밀번호 일치 검사는 주석으로 꺼져 있다.
  3. 2단계는 이름(최대 5자), 생년월일, 학교, 전공이다.
  4. "가입 완료"도 같은 nextStep을 호출하므로 2단계에 머문다. 가입 API 호출은 없다.
빈 값으로도 2단계로 넘어간다. 가입이 끝나도 로그인 화면으로 이동하지 않는다.

확인하는 법

/signup에서 "다음"과 "가입 완료"를 눌러 단계만 바뀌는지 본다. 로그인 링크는 /login으로 간다.

문제 풀이

무엇을 하나

주소의 부위와 영상 종류에 맞는 문제 이미지를 받아 큰 뷰어에 보여 준다.

어느 파일인가

  • CaseSolvingPage.vue — 문제를 불러오고 제출한다.
  • MedHeader.vue — 부위, 영상 종류, 사용자 메뉴.
  • CaseInfoBar.vue — 문제 번호와 요약.
  • XrayViewer.vue — 이미지와 ROI 레이어.

동작 순서

  1. 쿼리에서 region, type을 읽고 없으면 brain, CT를 쓴다.
  2. GET http://127.0.0.1:8000/learning/problem?st_part=...&st_modal=... 를 호출한다. 세션의 idx가 있으면 user_idx도 붙인다.
  3. 응답 problem.st_image를 받아 이미지 바이트를 내려받고, 그 파일 객체로 화면에 그린다.
  4. 이미지는 상대 경로와 http://125.134.136.59:3333 기준 주소를 차례로 시도한다.
  5. 실패하면 "문제 불러오는 중" 대신 오류 문장을 보여 준다. 문제가 없으면 "풀 수 있는 새 문제가 없습니다."다.

확인하는 법

/medical?region=chest&type=CT처럼 쿼리를 바꿔 헤더의 "흉부 · CT · 문제 풀이"가 바뀌는지 본다. 상단 "목록"은 아직 "케이스 목록 화면은 아직 연결 전입니다." 알림만 띄운다. "가이드"도 "가이드 준비 중입니다." 알림이다.

ROI와 채점

무엇을 하나

영상 위에 원이나 박스를 드래그해 관심 영역을 그리고, 마지막 영역만 서버에 보내 채점한다.

어느 파일인가

  • RoiToolbar.vue — 원, 박스, 지우기, 제출 버튼. 선택 도구는 부모의 tool과 연결된다.
  • RoiLayer.vue — 그린 도형을 이미지 위에 올린다.
  • CaseSolvingPage.vue — 화면 좌표를 이미지 비율 좌표로 바꿔 요청 본문을 만든다.

동작 순서

  1. 드래그가 끝나면 addRoi로 목록에 쌓인다. 지우기는 removeRoi다.
  2. 원본 이미지가 없거나 ROI가 없으면 알림을 띄우고 요청하지 않는다.
  3. 여러 개면 마지막 ROI만 사용한다. 화면 아래 안내 문과 같다.
  4. 도형이 잘리지 않게 들어간 실제 그림 영역을 계산한 뒤, 왼쪽·위·너비·높이를 0에서 1 사이 비율로 바꾼다.
  5. 원은 중심 cx, cy와 radius로, 박스는 x, y, width, height로 FormData에 넣는다. 이미지 파일도 함께 보낸다.
  6. POST http://127.0.0.1:8000/learning/roi-grade 가 끝나면 결과와 ROI를 sessionStorage 키 medlens.review에 저장하고 /medical/review로 이동한다.

확인하는 법

이미지를 불러온 뒤 제출만 누르면 ROI 안내 알림이 나온다. 박스를 그린 뒤 제출하면 주소가 /medical/review로 바뀌고, 개발자 도구에 medlens.review JSON이 생겨야 한다. 용량이 크면 오버레이 이미지 문자열은 빼고 다시 저장한다.

용어 사전

무엇을 하나

풀이 화면 오른쪽에 의학 용어 목록을 보여 준다. 문제 채점과는 별도 요청이다.

어느 파일인가

TermDictionary.vue. 풀이 페이지가 우측 칸으로 붙인다. 용어 데이터는 이 파일이 GET http://127.0.0.1:8000/glossary로 가져온다.

동작 순서

  1. 페이지가 열리면 용어 API를 호출한다.
  2. 서버가 배열 문자열로 준 값은 parsePgArray로 풀어 화면에 쓴다.
  3. 헤더와 같이 부위 코드 brain, chest, abdomen, knee를 한글 라벨로 바꾼다.

확인하는 법

풀이 화면에서 오른쪽 목록이 비거나 오류면 용어 API만 따로 의심하면 된다. 왼쪽 영상이 보여도 용어 요청은 따로 실패할 수 있다.

채점 리뷰

무엇을 하나

방금 제출한 영상, 내가 그린 영역, 서버 오버레이, 정답 여부를 나란히 보여 준다. 저장이 없으면 연습용 목업을 보여 준다.

어느 파일인가

  • CaseReviewPage.vue — 저장값을 읽어 두 패널에 넘긴다.
  • reviewModel.js — 저장 키, 목업, 오버레이 주소 변환.
  • ReviewResultPanel.vue — 영상과 ROI.
  • ReviewSummaryPanel.vue — 판정, IoU, 소견.
  • ReviewHeader.vue — 다음 문제, 학습 종료.

동작 순서

  1. 처음 데이터는 목업이다. usingMock이 참이고 판정은 "부분정답"이다.
  2. mounted에서 medlens.review를 읽는다. gradeResult가 없으면 목업을 유지한다.
  3. 있으면 목업 표시를 끄고 저장한 채점, 이미지 경로, 사용자 ROI, 오버레이를 쓴다.
  4. 오버레이는 저장된 경로가 우선이고, 없으면 응답의 base64 PNG를 이미지 주소로 만든다.
  5. "다음 문제"와 "학습 종료" 둘 다 같은 region, type으로 /medical에 돌아간다.
"학습 종료"가 풀이와 같은 주소로 간다. 목록이나 종료 화면은 아직 없다.

확인하는 법

제출 없이 /medical/review를 열면 목업 표시가 보여야 한다. 풀이에서 제출한 직후라면 방금 그린 영역과 서버 판정이 보여야 하고 목업 문구는 사라진다.

아직 안 된 것

무엇을 하나

아래는 화면은 있지만 동작이 명세서와 다른 부분이다. 구현하면 이 목록에서 지우고 해당 절의 동작 순서를 고친다.

어느 파일인가

  • 풀이·리뷰 로그인 강제는 src/router/index.js에 아직 없다.
  • 가이드 알림은 MedHeader.vue의 onGuide다.
  • 가입 검사와 API는 TodoRegisterInput.vue의 nextStep이다.
  • 학습 종료 이동은 CaseReviewPage.vue의 onDone이다.

동작 순서

  1. 세션 없이 /medical에 들어갈 수 있다.
  2. 가이드는 준비 중 알림만 띄운다.
  3. 회원가입은 빈 값도 통과하고 서버에 가입하지 않는다.
  4. 학습 종료는 다음 문제와 같은 풀이 화면으로 간다.

확인하는 법

각 버튼을 눌러 알림이나 이동이 위 설명과 같은지 본다. 달라졌다면 이 절부터 수정한다.
