앱이 뜨는 순서

무엇을 하나

브라우저가 Vue 앱을 붙이고, 주소에 맞는 화면 하나만 보여 준다. 공통 레이아웃은 없고 router-view만 있다.

어느 파일인가

  • src/main.js — 앱을 만들고 라우터를 연결한 뒤 #app에 붙인다.
  • src/App.vue — 화면 전환만 담당한다. 로그인 여부 판단은 하지 않는다.
  • public/index.html — #app이 있는 HTML 껍데기다.

동작 순서

  1. main.js가 createApp(App).use(router)를 호출한다.
  2. 지금 주소가 /, /login, /signup, /main, /learning, /medical, /medical/review 중 무엇인지 라우터가 고른다.
  3. 고른 페이지 컴포넌트가 App.vue 안에 그려진다.

확인하는 법

npm run serve 후 주소만 바꿔 본다. 레이아웃이 페이지마다 완전히 달라지면 App.vue가 뼈대만 제공하고 있다는 뜻이다.

폴더를 나눈 이유

무엇을 하나

화면을 기능 폴더에 모아, 로그인 작업을 할 때 영상 채점 파일을 열지 않게 한다.

어느 파일인가

폴더맡은 일
src/components/login/로그인 화면과 사용자 세션
src/components/signup/회원가입 2단계 폼
src/components/main/로그인 후 홈(인사, 바로가기, 학습 현황, 이벤트 팝업, 문의 채팅)
src/components/learning/학습 설정(부위, 영상 종류)
src/components/Medical/문제, 영상, ROI, 용어 사전
src/components/Medical/review/채점 결과를 다시 보는 화면
src/apiBase.js백엔드 주소 API_BASE. 요청 파일은 경로만 뒤에 붙인다

동작 순서

페이지 컴포넌트가 같은 폴더의 조각을 불러 조립한다. 예를 들어 로그인 페이지는 브랜드 영역과 입력 폼을 나란히 둔다. 세션을 읽고 쓰는 함수는 authSession.js 한곳에만 둔다. 채점 저장은 reviewModel.js만 맡는다.

확인하는 법

화면을 고칠 때 그 기능 폴더 밖 파일을 열어 보면 연결이 과한 것이다. 스타일은 각 .vue의 scoped CSS에 있다. 백엔드 호스트만 src/apiBase.js를 같이 쓴다.

백엔드 주소

무엇을 하나

로그인, 이벤트 팝업, 문의, 문제, 채점, 용어 요청이 같은 서버 주소를 쓴다. 주소를 바꿀 때는 한 줄만 고친다.

어느 파일인가

src/apiBase.js. 서버 호스트는 화면마다 다르지 않아서 기능 폴더 밖에 둔다. 각 요청 파일은 경로만 이 값 뒤에 붙인다.

동작 순서

  1. API_BASE 기본값은 http://127.0.0.1:8000이다.
  2. 로그인은 ${API_BASE}/login, 팝업은 /popups, 문의는 /qa, 문제는 /learning/problem, 채점은 /learning/roi-grade, 용어는 /glossary다.
  3. 영상 파일 주소(synology.me)는 이 값이 아니다. CaseSolvingPage.vue의 IMAGE_BASE에 따로 있다.
export const API_BASE = 'http://127.0.0.1:8000'
const LOGIN_API = `${API_BASE}/login`

확인하는 법

API_BASE를 다른 주소로 바꾼 뒤 로그인하거나 /main을 새로고침한다. 개발자 도구 Network의 /login, /popups, /qa가 그 주소로 가야 한다. 값을 되돌리면 다시 127.0.0.1:8000으로 간다.

주소와 로그인 이동

무엇을 하나

주소로 화면을 고르고, 로그인된 사람이 로그인 화면에 머물지 않게 한다.

어느 파일인가

src/router/index.js. 경로 표가 여기 있어야 화면을 추가할 때 한곳만 고치면 된다.

동작 순서

  1. / 는 세션이 있으면 /main, 없으면 /login으로 보낸다.
  2. /login 은 이미 세션이 있으면 /main으로 보낸다.
  3. /signup은 회원가입이다. /main, /learning, /medical, /medical/review는 requireSession이 세션을 확인하고, 없으면 /login으로 보낸다.
  4. 풀이 주소의 region은 뇌·흉부·복부·무릎(brain, chest, abdomen, knee)이고 type은 CT 같은 영상 종류다.

확인하는 법

로그인 전 /main, /learning, /medical, /medical/review를 주소창에 입력하면 로그인 화면이 나와야 한다. 로그인한 뒤 같은 주소를 열면 각 화면이 열린다.

로그인

무엇을 하나

아이디와 비밀번호를 서버에 보내고, 성공하면 메인 홈(/main)으로 간다. 실패하면 이유를 폼 위에 보여 준다.

어느 파일인가

  • LoginPage.vue — 요청과 이동. 입력창 모양은 모른다.
  • LoginForm.vue — 아이디, 비밀번호, 가입 링크.
  • LoginBrandPanel.vue — 왼쪽 소개 영역.

동작 순서

  1. 폼이 login 이벤트로 아이디와 비밀번호를 올린다.
  2. 페이지가 POST ${API_BASE}/login에 { userId, userPw }를 보낸다. 호스트는 src/apiBase.js다.

확인하는 법

백엔드가 127.0.0.1:8000에서 떠 있는 상태로 틀린 비밀번호와 맞는 계정을 각각 넣어 본다. 요청 중에는 로딩 상태가 폼에 전달된다.

세션

무엇을 하나

어느 파일인가

src/components/login/authSession.js. 저장 형식을 한곳에서 맞춰야 헤더, 라우터, 문제 API가 같은 사용자를 본다.

어느 파일인가

메인 홈

무엇을 하나

로그인한 사용자가 인사말·학습 바로가기·오늘의 학습 현황을 보는 홈 화면이다. 왼쪽 위에는 서버에서 받은 이벤트 홍보 팝업이 여러 장 뜨고, 제목 줄을 끌어 각 팝업을 옮길 수 있다. 헤더 "문의하기"로 채팅 창을 연다. 현황은 부위별로 나뉘고, 오늘 학습한 부위만 나온다. 오답노트·마이페이지·학습 기록 링크와 현황 수치는 아직 목업이다.

어느 파일인가

  • src/components/main/indexPage.vue — 홈 레이아웃, 세션 이름, 바로가기, 부위별 현황 카드. 팝업과 채팅을 붙인다.
  • src/components/main/MainHeader.vue — MedLens 브랜드, 학습·오답노트·마이페이지·문의하기, 이름·로그아웃 메뉴.
  • src/components/main/EventPromoPopups.vue — 이벤트 팝업 여러 장. 왼쪽 위에 두고, 제목 줄로 옮긴다. 닫기는 장마다 따로다.
  • src/components/main/eventPopups.js — GET /popups로 이벤트 목록을 받는다. "오늘 하루 보지 않기"만 그 날짜에 숨긴다.
  • src/components/main/InquiryChat.vue — 문의 채팅 창. 열고 있는 동안 최근 문의를 다시 읽는다.
  • src/components/main/inquiryChat.js — GET/POST ${API_BASE}/qa로 문의 스레드와 메시지를 다룬다.
  • src/components/main/todayStudyStats.js — 부위 라벨과 오늘 학습한 부위만 골라 주는 함수.
  • src/router/index.js — /main 경로와 세션 검사.

동작 순서

  1. 주소가 /main이면 requireSession이 세션을 확인한다. 없으면 /login으로 보낸다.
  2. indexPage가 getUserSession()으로 이름을 읽어 "안녕하세요, {이름}님"을 보여 준다.
  3. "학습하기"와 "학습 시작"은 /learning으로 이동한다. 헤더의 "학습"도 같다.
  4. 헤더 오른쪽 이름·아바타를 누르면 로그아웃이 나온다. 누르면 세션과 채점 저장을 지우고 /login으로 간다.
  5. 오답노트·마이페이지·학습 기록은 화면이 없어 클릭해도 이동하지 않는다.
  6. getStudiedRegionStats()가 오늘 학습한 부위만 남긴다. 각 부위마다 학습 시간·학습 문제·정답률을 보여 준다. 학습한 부위가 없으면 안내 문구를 보여 준다.
  7. fetchVisibleEventPopups()가 GET ${API_BASE}/popups를 호출한다. 각 항목의 pp_title, pp_image_url, pp_link, start_at·end_at을 쓰고 pp_sort 순으로 화면 왼쪽 위부터 나란히 띄운다. 기간은 제목 옆에 붙인다. 오늘 "오늘 하루 보지 않기"를 누른 idx는 빼다.
  8. 제목 줄을 누른 채 움직이면 그 팝업만 따라간다. ×와 "참여하기", "오늘 하루 보지 않기", "닫기" 위에서는 끌기가 시작되지 않는다. 옮긴 위치는 새로고침하면 왼쪽 위로 돌아간다.
  9. 한 장의 × 또는 "닫기"는 그 장만 지금 화면에서 없앤다. 저장하지 않아서 홈을 다시 열면 그 장도 다시 뜬다. 다른 장은 그대로 남는다.
  10. "오늘 하루 보지 않기"는 그 장의 idx와 오늘 날짜를 localStorage 키 medlens.eventDismissToday에 남긴다. 같은 날짜에 새로고침해도 그 장만 나오지 않고, 다른 장은 나온다.
  11. pp_link가 없으면 "참여하기"는 없다. http로 시작하면 새 탭으로 열고, /learning 같은 경로는 앱 안에서 이동한다.
  12. 팝업 요청이 실패하면 팝업만 비우고 홈의 나머지 화면은 그대로 둔다.
  13. 헤더 "문의하기"는 채팅 창을 연다. 세션 idx로 GET ${API_BASE}/qa?user_idx=를 호출해 가장 최근 스레드를 고르고, GET /qa/{idx}?user_idx=의 메시지를 보여 준다. qm_role이 U면 오른쪽, A면 왼쪽 담당자 말풍선이다. 문의가 없으면 화면용 인사만 보여 준다.
  14. 첫 글과 종료(state가 S)된 뒤의 글은 POST /qa에 { user_idx, title, body }를 보낸다. title은 내용 앞 40자다. 진행 중인 문의의 다음 글은 POST /qa/{idx}/messages에 { user_idx, body }를 보낸다. 입력칸에 글을 쓰기 전에는 열 때 한 번만 읽고, 글을 입력한 뒤부터 5초마다 같은 문의를 다시 읽어 담당자 답을 붙인다.
GET ${API_BASE}/popups
  → [{ idx, pp_title, pp_image_url, pp_link, pp_sort, start_at, end_at }, ...]
fetchVisibleEventPopups()
  → pp_sort 순. localStorage medlens.eventDismissToday 에 오늘 날짜로 숨긴 idx는 뺀다
  ×·닫기 → 저장 없이 그 장만 화면에서 제거
  오늘 하루 보지 않기 → 그 idx만 오늘 날짜로 저장

GET ${API_BASE}/qa?user_idx=
  → { items: [{ idx, qt_title, state, ... }] }
GET /qa/{idx}?user_idx=
  → { thread, messages: [{ idx, qm_role, qm_body, created_at }] }
POST /qa  { user_idx, title, body }
POST /qa/{idx}/messages  { user_idx, body }
오답노트·마이페이지·학습 기록 화면과 현황 API는 아직 없다. 부위별 수치는 todayStudyStats.js 목업이다. 문의가 하나도 없을 때의 인사 한 줄은 서버에 저장되지 않는다. 팝업 API나 문의 API가 꺼져 있으면 그 기능만 비고 홈의 나머지는 남는다.

확인하는 법

백엔드가 127.0.0.1:8000에서 떠 있는 상태로 로그인 후 /main을 연다. 화면 왼쪽 위에 /popups 항목 수만큼 팝업이 보이고, 제목 옆에 기간이, 그 아래 이미지가 응답과 같아야 한다. 제목 줄을 끌어 한 장만 다른 곳으로 옮겨지고 나머지는 그 자리에 있어야 한다. pp_link가 없는 항목에는 "참여하기"가 없다. 한 장만 × 또는 "닫기"를 누르면 그 장만 사라지고, 새로고침하면 그 장이 왼쪽 위에 다시 나와야 한다. 다른 장의 "오늘 하루 보지 않기"를 누른 뒤 새로고침하면 그 장만 오늘 다시 나오지 않아야 한다. 서버를 끄면 팝업은 없고 홈의 인사·바로가기는 남는다. 헤더 "문의하기"를 열면 그 계정(idx)의 최근 문의 메시지가 보여야 한다. 글을 보내면 오른쪽 말풍선에 쌓이고, 창을 닫았다가 다시 열어도 서버에 남은 글이 보인다. 담당자 답(qm_role A)은 왼쪽 말풍선이다.

동작 순서

  1. 주소 /learning은 세션이 없으면 /login으로 보낸다.
  2. 처음에는 부위·영상 종류가 비어 있고 "학습 시작"은 꺼져 있다.
  3. 부위를 고르기 전에는 영상 종류에 "부위를 먼저 선택해 주세요."를 보여 준다.
  4. 부위에 따라 영상 종류가 달라진다. 뇌·복부는 CT·MRI, 흉부는 X-ray만, 무릎은 MRI만.
  5. 부위를 바꾸면 이전 영상 종류가 맞지 않으면 선택을 지운다.
  6. 부위와 영상 종류가 모두 있을 때만 "학습 시작"이 켜진다.
  7. "학습 시작"은 /medical?region=...&type=...로 간다.
  8. 상단 이름·아바타를 누르면 로그아웃이 나온다. 누르면 세션과 채점 저장을 지우고 /login으로 간다.
  9. 사이드바의 학습 기록·북마크·리포트·설정은 아직 화면이 없다.
부위 chest + 영상 x-ray
  → /medical?region=chest&type=x-ray
사이드바의 학습 기록·북마크·리포트·설정 화면은 아직 없다.

확인하는 법

로그인 후 /learning을 연다. 처음에는 선택이 없고 "학습 시작"이 꺼져 있어야 한다. 부위와 영상 종류를 고른 뒤 "학습 시작"을 누르면 풀이 화면으로 가야 한다. 상단 이름에서 로그아웃하면 로그인 화면으로 간다. 메인 홈의 "학습하기"로도 이 화면이 열린다.

문제 풀이

무엇을 하나

주소의 부위와 영상 종류에 맞는 문제 이미지를 받아 큰 뷰어에 보여 준다. MRI는 경로가 여러 장이면 슬라이스를 넘기며 본다.

어느 파일인가

  • CaseSolvingPage.vue — 문제를 불러오고 제출한다. MRI 경로 배열 파싱과 슬라이스 로드도 여기서 한다.
  • MedHeader.vue — MedLens 로고(/main), 부위·영상 종류·문제 풀이, 가이드, 이름·로그아웃.
  • CaseInfoBar.vue — 문제 번호와 요약.
  • XrayViewer.vue — 이미지와 ROI 레이어. 슬라이스가 많으면 하단 슬라이더와 휠로 장을 바꾼다.

동작 순서

  1. 쿼리에서 region, type을 읽고 없으면 brain, CT를 쓴다.
  2. GET ${API_BASE}/learning/problem?st_part=...&st_modal=... 를 호출한다. 세션의 idx가 있으면 user_idx도 붙인다. 호스트는 src/apiBase.js다.
  3. type이 MRI이면 problem.st_image를 경로 배열(또는 JSON·PostgreSQL 배열 문자열)로 풀고, 그 외 종류는 첫 경로 한 장만 쓴다.
  4. 지금 슬라이스 경로의 이미지 바이트를 내려받아 파일 객체로 화면에 그린다. 받은 장은 캐시에 두고, 앞뒤 몇 장은 미리 받는다. 슬라이스를 바꾸면 ROI는 지운다.
  5. 이미지는 먼저 /stylesheets/...로 요청한다. 개발 서버가 이 경로를 https://olleh7531.synology.me/mu_shop/public로 넘긴다. 실패하면 같은 Synology 주소를 직접 한 번 더 호출한다.
  6. 실패하면 "문제 불러오는 중" 대신 오류 문장을 보여 준다. 문제가 없으면 "풀 수 있는 새 문제가 없습니다."다.

확인하는 법

로그인한 뒤 /medical?region=chest&type=CT는 한 장만 보이고 슬라이더가 없어야 한다. /medical?region=brain&type=MRI에서 Network의 /learning/problem 응답 st_image가 [로 시작하는 배열(또는 JSON 배열 문자열)일 때만 하단에 슬라이더가 나온다. 경로 문자열 한 개면 슬라이더 없이 한 장만 보인다. 한 번 지나친 장은 다시 빠르게 나와야 한다. 상단 "목록"은 아직 "케이스 목록 화면은 아직 연결 전입니다." 알림만 띄운다.

ROI와 채점

무엇을 하나

영상 위에 원이나 박스를 드래그해 관심 영역을 그리고, 마지막 영역만 서버에 보내 채점한다.

어느 파일인가

  • RoiToolbar.vue — 원, 박스, 지우기, 제출 버튼. 선택 도구는 부모의 tool과 연결된다.
  • RoiLayer.vue — 그린 도형을 이미지 위에 올린다.
  • CaseSolvingPage.vue — 화면 좌표를 이미지 비율 좌표로 바꿔 요청 본문을 만든다.

동작 순서

  1. 드래그가 끝나면 addRoi로 목록에 쌓인다. 지우기는 removeRoi다.
  2. 원본 이미지가 없거나 ROI가 없으면 알림을 띄우고 요청하지 않는다.
  3. 여러 개면 마지막 ROI만 사용한다. 화면 아래 안내 문과 같다.
  4. 도형이 잘리지 않게 들어간 실제 그림 영역을 계산한 뒤, 왼쪽·위·너비·높이를 0에서 1 사이 비율로 바꾼다.
  5. 원은 중심 cx, cy와 radius로, 박스는 x, y, width, height로 FormData에 넣는다. 이미지 파일도 함께 보낸다.
  6. type이 MRI이면 slice_index(0부터)와 현재 슬라이스 image_path를 추가로 넣는다. CT는 이 두 필드를 보내지 않는다.
  7. POST ${API_BASE}/learning/roi-grade 가 끝나면 결과와 ROI, 슬라이스 정보를 sessionStorage 키 medlens.review에 저장하고 /medical/review로 이동한다.

확인하는 법

이미지를 불러온 뒤 제출만 누르면 ROI 안내 알림이 나온다. 박스를 그린 뒤 제출하면 주소가 /medical/review로 바뀌고, 개발자 도구에 medlens.review JSON이 생겨야 한다. MRI면 JSON에 sliceIndex, imagePath가 있어야 한다. 용량이 크면 오버레이 이미지 문자열은 빼고 다시 저장한다.

채점 리뷰

무엇을 하나

방금 제출한 영상, 내가 그린 영역, 서버 오버레이, 정답 여부를 나란히 보여 준다. 요약에는 출혈(ICH) 확률과 생식세포종양(germinoma) 확률을 함께 보여 준다. MRI면 몇 번째 슬라이스를 냈는지도 보여 준다. 저장이 없으면 연습용 목업을 보여 준다.

어느 파일인가

  • CaseReviewPage.vue — 저장값을 읽어 두 패널에 넘긴다.
  • reviewModel.js — 저장 키, 목업(출혈·germinoma 포함), 오버레이·슬라이스 값 변환.
  • ReviewResultPanel.vue — 영상과 ROI, MRI 슬라이스 배지.
  • ReviewSummaryPanel.vue — 판정, IoU, 출혈(ICH)·Germinoma 소견, 제출 슬라이스.
  • ReviewHeader.vue — 다음 문제, 학습 종료.

동작 순서

  1. 처음 데이터는 목업이다. usingMock이 참이고 판정은 "부분정답"이다. 목업에도 출혈·생식세포종양 예시가 있다.
  2. mounted에서 medlens.review를 읽는다. gradeResult가 없으면 목업을 유지한다.
  3. 있으면 목업 표시를 끄고 저장한 채점, 이미지 경로, 사용자 ROI, 오버레이, sliceIndex/sliceTotal을 쓴다.
  4. 요약의 "주요 영상 소견"은 gradeResult.classification.findings(출혈 ICH)와 gradeResult.germinoma.findings(생식세포종양)를 확률 막대로 보여 준다. germinoma가 null이면 Germinoma 줄은 생략한다.
  5. 오버레이는 저장된 경로가 우선이고, 없으면 응답의 base64 PNG를 이미지 주소로 만든다.
  6. MRI이고 슬라이스 값이 있으면 결과 배지와 요약에 "슬라이스 N / M"을 보여 준다.
  7. "다음 문제"는 같은 region, type으로 /medical에 돌아간다.
  8. "학습 종료"는 onDone이 /main으로 보낸다. 세션은 유지된다.
gradeResult.classification.findings  → 출혈 (ICH) 막대
gradeResult.germinoma.findings       → Germinoma · 생식세포종양 막대

확인하는 법

로그인한 뒤 제출 없이 /medical/review를 열면 목업에 출혈·생식세포종양 예시가 보여야 한다. 세션이 없으면 로그인 화면으로 간다. 풀이에서 제출한 직후라면 방금 그린 영역과 서버 판정이 보여야 하고, Network/medlens.review의 germinoma가 있으면 요약에 Germinoma 줄이 나와야 한다. "학습 종료"를 누르면 메인 홈(/main)으로 가야 한다.
